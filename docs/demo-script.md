## 镜头内执行的唯一入口

在 openKylin VM 终端执行：

```bash
bash ~/KylinMemoryBench/video-prep-20261013/run-on-camera.sh
```

它会实际执行 `official-repeat`：KylinBot / OpenClaw、quick 六案例、seed 42、repeats 1、timeout 180、临时 HOME 隔离；结束后自动检查有效性及 strict。录制前已用 `--check` 检查入口，正式录制不带此参数。

开始前确认 `ready.json` 中 status 为 ready，并且正式输出目录还未执行过。如需要重新准备，在镜头外运行：

```bash
python3 ~/KylinMemoryBench/video-prep-20261013/prepare-video.py
```

准备脚本只做预检并预留新目录，不启动真实 Agent 对话。不要使用之前执行过的目录重录。

## 运行后的页面定位

以终端显示的本次目录为准。在“运行历史”点击刷新，清空旧筛选，再搜索本次 `video-real-...` 目录名。选择 `evaluation/repeat-01/quick-compare` 的 **kylinbot + openclaw** 双 Agent 条目，点击“打开”。在结果中心展示“概览 / 对比 → 案例 → quick-update → 打开证据”。

当前预留目录为 `runs/video-real-20261013-203622/`；如果重新准备，目录会变化。`real-022-r2` 是旧预演，不作为新现场运行结果。

## 案例补充句（只选与本次证据一致的一句）

- 检查通过：“这一项通过，是因为这里的实际答复或状态证据满足了目标检查。”
- 回答包含新值且含禁止旧值：“答复包含 Room B，这一项通过；同时出现了案例禁止的 Room A，所以禁词项未通过。提到旧值不能单独证明它实际用了旧会议室。”

## 备课边界（不念）

`memory_absent otp` 的目标键检查不能证明所有文件均未保存信息；旧预演的 conversation 行中含合成验证码，不能以键检查通过宣称“完全未保存”。正式主讲选择 quick-update，按实际规则与引用解释。
