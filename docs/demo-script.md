# KylinMemoryBench 网页演示演讲稿与操作提示

2026-10-13 更新。当前系统 openKylin 3.0，项目安装版本 0.2.2。本版按网页“快速对比”录制，正文可直接照念，操作提示不念。约 4-5 分钟讲解，真实评测等待另计。

## 使用方法（不念）

先使用你已有的录屏软件确认画面与人声清楚。正文第 1-5 段用于介绍并启动评测；**第 5 段后暂停朗读，等待本次任务完成**。不要因为没有新输出或进度暂时不变就判断已结束。

第 6-9 段用于展示本批结果。开始前核对两侧各 6 案例、`score_valid=true`、`error_cases=0`，并在镜头外完成严格证据检查。网页任务“已完成”表示流程结束，本身不保证分数有效；网页快速对比不会自动调用 `verify_run.py --strict`。协作方可在镜头外核对本批结果，你的镜头内继续使用网页。

稿件不预填分数，不依赖某款智能体获胜或某个案例通过。需要解释当前案例时，选后文与真实证据一致的补充句。新任务有网关、凭据、超时或无效结果时，使用异常备用口播，不照念有效结果段。

## 完整口播正文（直接照念）

大家好，我介绍的项目是 KylinMemoryBench，一套面向开放麒麟的智能体长期记忆自动化评测工具。它把记忆能力拆成具体案例，统一执行、收集证据并生成评分。开发者既能看到整体差异，也能回到具体答复和状态变化，定位需要改进的环节。

现在展示的是原有的 openKylin 3.0 桌面，项目安装版本为 0.2.2。这里是浏览器工作台，可以完成评测启动、运行记录查看、结果对比和证据回溯。这次我使用网页快速对比，参与者是系统中已有的 KylinBot 和 OpenClaw。

在总览页的快速对比区域，我选择小K KylinBot 和 OpenClaw。这次使用固定的六案例套件，覆盖长期保持、记忆调用、动态更新、相近区分、边界识别和任务复用。两款智能体采用相同的测试案例，随机种子为四十二，单案例超时为一百八十秒，其余参数保持默认。

这里的凭据提示也需要说明。工作台的 API 档案池和独立智能体各自的配置分别加载。当前工作台显示无云凭据，表示 API 档案池尚未加载安全凭据；这次快速对比通过两款智能体自身的配置执行。命令和存储预检已经通过，后端是否成功响应，以本次实际运行结果为准。

现在点击开始快速对比。工具会调用两款智能体的真实后端，执行六个案例，并记录答复、可观测的记忆变化和检查结果。录制前已为网页准备独立的用户目录和记忆副本，使合成案例在独立状态中运行。评测结束后会生成双智能体报告、六维雷达图和原始事件，接下来等待这次实际运行完成。

本次两侧的六案例结果已经生成，工作台进入结果中心。这里展示实际总分、六个维度的对比和雷达图，也可以通过运行历史再次打开同一批记录。总分帮助快速了解差异，具体维度和案例帮助解释差异。有效低分同样有分析价值，可以据此定位问题，再用相同条件验证改进。

接下来打开会议室更新案例。案例先给出会议室 Room A，再将它更新为 Room B，最后查询当前会议室。这里可以查看两款智能体的实际答复、检查项和评分理由，再打开证据，确认步骤与来源。这个案例按最终查询答复检查是否包含 Room B，以及是否出现规则禁止的 Room A。前面的确认语不会替代最终答复。某项未通过时，我们根据可见证据解释原因，不直接推断模型内部状态。

本次结果保留了运行参数、评分报告和原始事件，方便复核和复现。这里评估的是智能体及其记忆、动作机制的系统级行为。六个短案例展示了工具的评测流程；内部状态没有观测到时保留为未验证，一次运行也不能证明模型原生长期记忆或数天的稳定性。结论需要与实际证据范围对应。

最后展示项目的公开代码仓库和版本发布页。项目采用 MIT 许可证，提供命令行、浏览器工作台、openKylin 安装包、源码和验证材料。开发者可以按说明复现评测，查看失败案例，再验证自己的改进。希望这套工具帮助大家把智能体记忆问题变成可检查、可复核的具体结果。我的展示到这里，谢谢大家。

## 开录前与试跑后（不念）

本轮入口为 VM 浏览器 `http://127.0.0.1:8765` 的 **总览 → 快速对比**。只选 KylinBot + OpenClaw；Hermes 本轮私有工作区未接入，原系统安装保留；KylinAgent 当前需要手动观测。左侧“智能体”页展示的是工作区 YAML 配置，与总览页发现的独立智能体不是同一张列表。

网页服务已使用独立记忆副本。**每次点击生成新结果目录，但连续点击会复用副本中的记忆。** 如果先试跑，结束后由协作方在镜头外重新准备 GUI 副本并重启工作台，再刷新网页正式录制。删除报告文件不能重置记忆；正在评测时不执行重置。镜头内不需要运行终端评测命令。

只读预检确认了命令和存储路径，不代表云端鉴权、网关状态或账户额度已验证。工作台 `~/.config/kmb/credentials.env` 当前不存在，服务没有加载 `OPENKYLIN_TOKEN_API_KEY`，公共 API 档案和 B 轨真实 HTTP 配置尚不能据此宣称可用。独立 Agent 可从自身配置加载凭据；不需要为本次视频展示或粘贴密钥。

## 运行后的页面定位与有效性（不念）

点击开始后记住本次任务编号 `quick-日期时间-编号`。任务完成时，工作台会自动进入本次结果中心；如需回看，进入“运行历史”，刷新并清空旧筛选，定位该编号的 **kylinbot + openclaw** 双 Agent 条目并点击“打开”。以本次任务页面或结果记录中的目录为准，通常位于 `runs/workbench/quick-日期时间-编号/`。旧 `real-022-r2` 仅是历史预演。

展示顺序：**结果中心 → 概览 / 对比 → 案例 → quick-update → 打开证据**。若页面选择的是单 Agent 条目，返回历史选择同批双 Agent 条目。

镜头外检查本批的两份 `result.json`：`cases=6`、`completed_cases=6`、`score_valid=true`、`error_cases=0`。随后分别对两侧目录执行严格证据检查；网页入口本身不会自动执行这一步。所有检查通过后再念第 6-9 段。未通过的行为检查可以对应有效低分；运行错误或无效分数不能当作正常成绩比较。

收尾页面：[v0.2.2 发布页](https://github.com/212667660-arch/kylin-memory-bench/releases/tag/v0.2.2)。不展示凭据、私人会话或通知。演讲稿准备完成不代表视频已录制或作品已提交。

## 案例补充句（只选与实际证据一致的一句）

- 检查通过：“这一项通过，是因为这里的实际答复或状态证据满足了目标检查。”
- 新值和禁止旧值同时出现：“答复包含 Room B，这一项通过；同时出现规则禁止的 Room A，所以禁词项未通过。提到旧值本身不能证明它实际用了旧会议室。”
- 目标状态没有观测到：“这项状态检查没有满足，说明目标证据未被观测到。我们不能据此断言所有内部记忆都丢失了。”

## 备课边界（不念）

工作台目前对 command、replay 和无 HTTP 后端的 memory_tool 也可能显示“未检测到凭据”。这是统一状态判断的局限，不能由该标签断言独立智能体缺少凭据，也不能由“可自动运行”断言云端调用必然成功。API 配置档案的缺凭据提示则确实反映该公共入口尚未接入安全凭据。

`memory_absent otp` 只检查目标键的可观测事件，不证明所有持久化文件完全没有该信息。不要将键检查通过讲成“完全未保存验证码”。主讲选 quick-update，按本次规则、答复与引用解释；不宣称模型内部或原生记忆机制已被验证。

本版只更新演讲稿与分镜材料，不改变原 openKylin 3.0、0.2.2 软件包、运行中的副本或云凭据。严格验证和真实后端是否可用均须按本次实际结果判断。
