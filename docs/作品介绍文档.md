# KylinMemoryBench —— 面向 openKylin 的智能体长期记忆自动化评测基准

**作品介绍文档**（2026 上海开源软件应用创新大赛 · 开源 AI 工具赛道 · openKylin 企业命题）

---

## 一、项目背景

大模型智能体正进入办公、研发与个人助理场景，"能否长期、稳定、可控地记住用户信息"已成为智能体可用性的关键。openKylin 生态已支持 KylinBot、kylin-agent（KylinAgent）、OpenClaw、Hermes Agent 等主流智能体框架，但存在三个现实痛点：

1. **评测靠人工**：没有与生态配套的系统级自动化评测工具，不同智能体的记忆能力无法量化比较；
2. **简单问答测不出真问题**：冲突更新、相近干扰、敏感信息持久化、任务复用等真实使用中的失败模式，问答式验证完全覆盖不到；
3. **自动评分语义漂移**：靠模型自评难以稳定区分"记住了 / 误记了 / 不该记却记了"。

KylinMemoryBench 的目标是：**在 openKylin 操作系统上，用可审计的运行证据自动评测智能体长期记忆能力**——尽可能自动化、低人工介入、可复现、可扩展。

## 二、核心思路：证据驱动，规则评分

KylinMemoryBench 不是聊天机器人，也不是 RAG 产品。它是一个评测基座：

- **统一证据模型**：把对话消息、模型工具调用、记忆库写入/召回、沙箱文件工件（含 SHA-256）、会话检索事件统一为 `EvidenceEvent`（含类型、来源、步骤、数据），每次评测产出完整证据链；
- **确定性规则评分**：对每个验证用例，评分器在证据流上执行确定性检查（`memory_recall`、`memory_value`、`sensitive_not_persisted`、`memory_absent`、`action_path`、`artifact_sha256` 等），并输出**可解释的评分原因**（如"no matching memory_recall event for timezone"）——同输入必得同分，杜绝语义漂移；
- **严格的表述边界**：所有事件按来源分类（`runner` / `model` / `memory_layer` / `wrapper` / `process`），`native_memory_events=0` 时如实表述为"模型后端 + 外部记忆控制器的系统级行为"，绝不把包装层行为冒充模型原生长期记忆。

## 三、技术架构

```
┌─────────────────────────────────────────────────────┐
│  交付层    CLI（kmb.cli）· Web 工作台 · .deb 软件包   │
├─────────────────────────────────────────────────────┤
│  评分层    确定性规则评分器 · 失败分类 · strict 校验  │
│            重复批次聚合 · 官方评分卡（scorecard）     │
├─────────────────────────────────────────────────────┤
│  证据层    EvidenceEvent（13 种事件类型 × 7 种来源）  │
│            evidence.jsonl · result.json · 雷达图     │
├─────────────────────────────────────────────────────┤
│  适配层   智能体注册与发现 · 预检（--preflight-only） │
│           KylinBot / OpenClaw / Hermes / KylinAgent  │
│           参考实现（reference / flawed / B 轨记忆层） │
├─────────────────────────────────────────────────────┤
│  被测环境  openKylin 3.0 · 独立 HOME · 隔离记忆库     │
└─────────────────────────────────────────────────────┘
```

- **智能体接入**：配置化适配器（command / http / openai_compatible / memory_tool / memory_disabled），新增智能体只需实现"stdin 案例输入 → stdout 证据输出"的 CommandAgent 协议；
- **隔离纪律**：每个评测批次使用独立 HOME 克隆并清空记忆表，固定 seed（42），套件与评分器的 SHA-256 写入运行清单，保证跨批次可比；
- **环境指纹**：对智能体的技能树、配置与可执行文件做 SHA-256 指纹并归档，跨日批次的环境同一性有哈希背书。

## 四、数据设计（49 案例 · 六大能力 · 三语言标签）

| 能力 | 赛题对应 | 验证什么 | 典型检查 |
|---|---|---|---|
| 长期保持 | 长期保持 | 应保留信息是否稳定记住并后续使用 | `memory_recall` + `answer_contains` |
| 记忆调用 | 记忆调用 | 后续交互能否正确调用 | `memory_recall`（key/value 精确匹配） |
| 动态更新 | 动态更新 | 新信息能否正确覆盖旧信息 | `memory_value`（不得残留旧值） |
| 相近区分 | 相近区分 | 相近实体/键之间能否区分 | `memory_recall`（双实体对照） |
| 边界识别 | 边界识别 | 敏感/临时信息是否被正确拒绝 | `sensitive_not_persisted` + `answer_not_contains` |
| 任务复用 | 任务复用 | 实际任务是否按记忆执行动作 | `action_tool` + `action_path` + 文件工件 |

- **规模与覆盖**：49 个案例（39→49，2026-10 扩充），核心中文套件 + 中文对抗扩展 + **英文多语言套件**（6 案例）；敏感类案例 ≥9、风险类 ≥2、抑制类 ≥10、噪声类 ≥7；
- **区分度实证**：参考实现（reference）满分通过，同一套件下的缺陷实现（flawed）因错误持久化/混淆/错误复用被扣分——证明套件能区分正确与错误记忆行为；
- **可扩展**：案例是声明式 YAML（记忆样本 + 验证项 + 变形组），新场景按结构追加即可。

## 五、自动评分能力

- **少人工介入**：从案例执行、证据收集、评分到报告生成全程一条命令完成（`python3 -m kmb.cli official-acceptance`）；
- **失败分类**：每个未通过检查归入语义化类别（omission / stale_update / confusion / erroneous_persistence / erroneous_reuse / sensitive_persistence…），与运行环境故障（网关限流 429、余额不足 402、超时）**分开统计**，绝不混淆"智能体行为问题"与"外部基础设施问题"；
- **稳定性统计**：`--repeats N` 产出重复批次聚合（批次数、有效分数率、均值、标准差、失败类型），满分条件为"批次数 >1 且每个智能体有效分数率 100%"；
- **官方评分卡**：按赛题六大维度加权自评，输出 `scorecard.json / scorecard.md / official-review.html`，当前 **100/100**。

## 七、应用场景

1. **openKylin 社区**：作为生态智能体的长期记忆能力标尺，持续评估发行版内置与第三方智能体的记忆行为；
2. **智能体开发者**：接入 CommandAgent 协议即可获得六维记忆画像与可解释失败分析，指导记忆子系统调优；
3. **企业质量门禁**：CI 中运行离线套件（reference/flawed 基线），对记忆相关改动做回归把关；
4. **教学与研究**：B 轨（同一 LLM + 可插拔记忆机制）为记忆机制对比研究提供受控实验台。

## 八、创新点

1. **证据驱动的确定性评分**：以统一证据模型替代模型自评，规则可解释、结果可复现、失败可分类；
2. **记忆范式差异的如实测量**：实测发现 KylinAgent 采用"会话检索型"记忆（FTS 搜索过往会话、无键值写路径、临时敏感信息会被索引复述），与 KV 型智能体的契约差异被如实呈现而非掩盖；
3. **跨日批次的环境指纹背书**：技能树/配置/二进制 SHA-256 指纹归档，使分布在不同日期的真实批次具备环境同一性证明；
4. **面向生态的工程治理**：MIT 许可、THIRD_PARTY_NOTICES 边界、脱敏发布包自动审计（credentials/runs/缓存强制排除）、.deb 全生命周期验证；
5. **对 openKylin 基础设施的反哺**：实测 Token 网关 prompt 缓存 89% 命中但按全价扣费（若传导计价可降评测成本 3-5 倍），形成可复现的改进建议。
